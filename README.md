# ابزار انتقال خودکار پروژه از دیسک به گیت‌هاب

این مجموعه شامل یک اسکریپت PowerShell و یک فایل Batch است که به شما امکان می‌دهد پروژه‌ای را که روی دیسک سیستم خود دارید (برای مثال در مسیر `D:\Projects`) به‌صورت خودکار به یک مخزن (Repository) در گیت‌هاب ارسال (Push) کنید. این ابزار برای کاربرانی طراحی شده که تجربه فنی کمی با خط فرمان دارند و می‌خواهند با حداقل دخالت دستی، تغییرات پروژه خود را روی گیت‌هاب منتشر کنند.

## محتویات پروژه

- `push-to-github.ps1` : اسکریپت اصلی PowerShell که تمام منطق اجرای دستورات Git را مدیریت می‌کند.
- `push-to-github.bat` : فایل Batch که با دابل‌کلیک اجرا می‌شود و با پرسیدن چند سؤال ساده، اسکریپت PowerShell را برای شما اجرا می‌کند.
- `config.example.json` : نمونه‌ای از تنظیمات قابل استفاده (مسیر پروژه، آدرس مخزن، پیام کامیت، نام شاخه) صرفاً جهت مستندسازی و مرجع؛ این فایل توسط اسکریپت‌ها خوانده نمی‌شود و فقط برای یادآوری مقادیر مورد نیاز است.
- `README.md` : همین فایل راهنما.

## پیش‌نیازها

پیش از استفاده از این ابزار، موارد زیر باید روی سیستم شما (ویندوز) فراهم باشد:

1. سیستم‌عامل ویندوز ۱۰ یا ۱۱ با PowerShell نسخه ۵.۱ یا بالاتر (این نسخه به‌صورت پیش‌فرض روی ویندوز نصب است).
2. نصب بودن برنامه Git برای ویندوز. در صورت عدم نصب، از آدرس رسمی زیر دانلود و نصب کنید:
   https://git-scm.com/download/win
   پس از نصب، یک بار Command Prompt یا PowerShell را ببندید و دوباره باز کنید تا مسیر Git در PATH سیستم شناسایی شود. برای بررسی صحت نصب می‌توانید دستور زیر را در PowerShell اجرا کنید:
   git --version
3. داشتن یک حساب کاربری در گیت‌هاب (GitHub) و یک مخزن (Repository) از پیش ساخته‌شده در آن حساب. اگر مخزن را هنوز نساخته‌اید، ابتدا از طریق وب‌سایت گیت‌هاب یک مخزن خالی (بدون README اولیه در صورت امکان، برای جلوگیری از تداخل) ایجاد کنید و آدرس آن را یادداشت کنید. آدرس مخزن معمولاً یکی از دو شکل زیر است:
   - https://github.com/username/repo.git
   - git@github.com:username/repo.git
4. دسترسی به اینترنت برای برقراری ارتباط با سرورهای گیت‌هاب.

## نکات مهم درباره احراز هویت گیت‌هاب

گیت‌هاب از اواسط سال ۲۰۲۱ دیگر ورود با نام کاربری و رمز عبور معمولی را برای عملیات Git از طریق HTTPS نمی‌پذیرد. برای اینکه عملیات `git push` با موفقیت انجام شود، باید یکی از روش‌های احراز هویت زیر را از پیش تنظیم کرده باشید.

### روش اول: استفاده از HTTPS همراه با Personal Access Token (PAT) — پیشنهادی برای اکثر کاربران

1. وارد حساب گیت‌هاب خود شوید.
2. به مسیر Settings سپس Developer settings سپس Personal access tokens سپس Tokens (classic) یا Fine-grained tokens بروید.
3. یک توکن جدید با دسترسی حداقل `repo` بسازید و آن را در جایی امن ذخیره کنید (این توکن فقط یک بار نمایش داده می‌شود).
4. هنگامی که اسکریپت برای اولین بار دستور `git push` را اجرا می‌کند، یک پنجره یا پیام برای وارد کردن نام کاربری و رمز عبور ظاهر می‌شود. در این حالت:
   - در فیلد نام کاربری، نام کاربری گیت‌هاب خود را وارد کنید.
   - در فیلد رمز عبور، به‌جای رمز عبور معمولی، همان Personal Access Token را وارد کنید.
5. ویندوز به‌طور پیش‌فرض از Git Credential Manager استفاده می‌کند که این اطلاعات را پس از اولین ورود موفق، به‌صورت امن ذخیره می‌کند تا در دفعات بعد دوباره از شما پرسیده نشود.

### روش دوم: استفاده از SSH

1. در صورتی که از قبل کلید SSH ندارید، با دستور زیر در PowerShell یک جفت کلید بسازید:
   ssh-keygen -t ed25519 -C "your_email@example.com"
2. محتوای فایل کلید عمومی (معمولاً در مسیر `C:\Users\YourName\.ssh\id_ed25519.pub`) را کپی کنید.
3. در گیت‌هاب به مسیر Settings سپس SSH and GPG keys سپس New SSH key بروید و کلید عمومی را اضافه کنید.
4. در این حالت آدرس مخزن را به‌جای فرمت HTTPS، با فرمت SSH وارد کنید، برای مثال:
   git@github.com:username/repo.git
5. در اولین اتصال ممکن است پیامی مبنی بر تأیید اعتبار میزبان (host fingerprint) نمایش داده شود؛ با وارد کردن `yes` آن را تأیید کنید.

اگر مطمئن نیستید کدام روش را انتخاب کنید، روش اول (HTTPS همراه با Personal Access Token) برای اکثر کاربران ساده‌تر و کافی است.

## روش اول اجرا: استفاده از فایل push-to-github.bat (ساده‌ترین روش، بدون نیاز به دانش فنی)

این روش مناسب کاربرانی است که نمی‌خواهند با خط فرمان یا پارامترهای PowerShell سر و کار داشته باشند.

مراحل:

1. مطمئن شوید دو فایل `push-to-github.ps1` و `push-to-github.bat` در یک پوشه کنار هم قرار دارند. این دو فایل باید همیشه در کنار هم باشند، در غیر این صورت فایل bat پیام خطا نمایش خواهد داد.
2. روی فایل `push-to-github.bat` دوبار کلیک کنید تا اجرا شود. یک پنجره سیاه‌رنگ (Command Prompt) باز می‌شود.
3. به ترتیب سؤالات زیر از شما پرسیده می‌شود:
   - مسیر پوشه پروژه روی دیسک. اگر کلید Enter را بدون وارد کردن مقدار بزنید، مقدار پیش‌فرض `D:\Projects` استفاده می‌شود. در صورت نیاز می‌توانید مسیر دقیق‌تری مانند `D:\Projects\MyApp` وارد کنید.
   - آدرس مخزن گیت‌هاب. این مقدار اجباری است و باید به شکل `https://github.com/username/repo.git` یا `git@github.com:username/repo.git` وارد شود.
   - پیام کامیت. در صورت خالی گذاشتن، پیام پیش‌فرض «بروزرسانی خودکار پروژه» استفاده می‌شود.
   - نام شاخه (Branch). در صورت خالی گذاشتن، مقدار پیش‌فرض `main` استفاده می‌شود.
4. خلاصه‌ای از اطلاعات وارد شده نمایش داده می‌شود. با وارد کردن `Y` عملیات را تأیید و ادامه دهید، یا با وارد کردن `N` عملیات را لغو کنید.
5. در صورت تأیید، اسکریپت PowerShell به‌صورت خودکار اجرا می‌شود و مراحل زیر را طی می‌کند: بررسی نصب بودن Git، بررسی وجود مسیر پروژه، مقداردهی یا به‌روزرسانی مخزن گیت محلی، تنظیم remote با نام origin، افزودن فایل‌ها (Add)، ثبت تغییرات (Commit) و ارسال به گیت‌هاب (Push).
6. در پایان، پیام موفقیت یا خطا به‌همراه کد خطا نمایش داده می‌شود و پنجره تا زمان فشردن یک کلید باز می‌ماند تا بتوانید پیام‌ها را مطالعه کنید.

در صورت بروز خطای احراز هویت در این مرحله، یک پنجره مجزا برای وارد کردن نام کاربری و Personal Access Token گیت‌هاب ظاهر می‌شود که باید طبق توضیحات بخش احراز هویت در همین فایل تکمیل شود.

## روش دوم اجرا: اجرای مستقیم اسکریپت PowerShell با پارامترها

این روش برای کاربرانی مناسب است که می‌خواهند کنترل بیشتری روی مقادیر ورودی داشته باشند یا بخواهند اجرای اسکریپت را در فرآیندهای خودکار (مانند Task Scheduler) قرار دهند.

### باز کردن PowerShell در مسیر پروژه اسکریپت

ابتدا یک پنجره PowerShell باز کنید و با دستور `cd` به پوشه‌ای بروید که فایل `push-to-github.ps1` در آن قرار دارد، برای مثال:

cd "D:\Tools\push-to-github"

### اجرای اسکریپت با تمام پارامترها

.\push-to-github.ps1 -ProjectPath "D:\Projects\MyApp" -RepoUrl "https://github.com/username/repo.git" -CommitMessage "بروزرسانی طراحی" -BranchName "main"

### توضیح پارامترها

- ProjectPath
  مسیر پوشه پروژه روی دیسک که قرار است به گیت‌هاب ارسال شود. اگر این پارامتر ارسال نشود، مقدار پیش‌فرض `D:\Projects` استفاده می‌شود. اگر پوشه `.git` در این مسیر وجود نداشته باشد، اسکریپت به‌صورت خودکار دستور `git init` را اجرا می‌کند و مسیر را به یک مخزن گیت محلی تبدیل می‌کند. اگر پوشه `.git` از قبل وجود داشته باشد، اسکریپت از همان مخزن موجود استفاده می‌کند و آن را از نو ایجاد نمی‌کند.

- RepoUrl
  آدرس مخزن گیت‌هاب که باید با `https://` یا `git@` شروع شود. این پارامتر برای تعیین مقصد Push الزامی است. اگر ارسال نشود، اسکریپت به‌صورت تعاملی آن را از شما می‌پرسد. اگر مخزنی با نام remote برابر `origin` از قبل در پروژه تعریف شده باشد، اسکریپت آدرس آن را با مقدار جدید به‌روزرسانی می‌کند؛ در غیر این صورت یک remote جدید با نام `origin` ایجاد می‌کند.

- CommitMessage
  متن پیام کامیت. اگر ارسال نشود، یک پیام پیش‌فرض همراه با تاریخ و ساعت اجرای اسکریپت به‌صورت خودکار تولید می‌شود، مثلاً: «بروزرسانی خودکار پروژه - 1403/05/12 14:30». اگر پس از اجرای `git add -A` هیچ تغییری در فایل‌ها وجود نداشته باشد، اسکریپت یک کامیت خالی نمی‌سازد و با پیام مناسب این موضوع را اطلاع می‌دهد.

- BranchName
  نام شاخه (Branch) که تغییرات باید روی آن Push شوند. مقدار پیش‌فرض `main` است. در صورت نیاز می‌توانید مقادیر دیگری مانند `master` یا `develop` را وارد کنید. اسکریپت در صورت نیاز شاخه را به همین نام در مخزن محلی ایجاد یا تغییر می‌دهد و با گزینه `-u` آن را به شاخه مشابه در گیت‌هاب متصل (Track) می‌کند.

### مثال‌های بیشتر

اجرای اسکریپت فقط با مسیر پروژه و آدرس مخزن (استفاده از مقادیر پیش‌فرض برای پیام کامیت و نام شاخه):

.\push-to-github.ps1 -ProjectPath "D:\Projects\RedesignApp" -RepoUrl "https://github.com/username/redesign-app.git"

اجرای اسکریپت بدون هیچ پارامتری (استفاده از مسیر پیش‌فرض D:\Projects و دریافت تعاملی آدرس مخزن):

.\push-to-github.ps1

اجرای اسکریپت با آدرس SSH:

.\push-to-github.ps1 -ProjectPath "D:\Projects\MyApp" -RepoUrl "git@github.com:username/repo.git" -BranchName "main"

### نکته درباره Execution Policy در PowerShell

در صورتی که هنگام اجرای مستقیم اسکریپت با دستور `.\push-to-github.ps1` با پیامی مبنی بر غیرفعال بودن اجرای اسکریپت‌ها مواجه شدید، می‌توانید از یکی از دو روش زیر استفاده کنید:

روش موقت فقط برای همین پنجره PowerShell:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

یا اجرای مستقیم با دور زدن سیاست اجرا بدون تغییر تنظیمات کلی سیستم:

powershell -NoProfile -ExecutionPolicy Bypass -File "push-to-github.ps1" -ProjectPath "D:\Projects\MyApp" -RepoUrl "https://github.com/username/repo.git"

فایل `push-to-github.bat` به‌صورت پیش‌فرض همین روش دوم را به کار می‌برد، بنابراین کاربرانی که از فایل bat استفاده می‌کنند نیازی به تغییر تنظیمات Execution Policy ندارند.

## توضیح فایل config.example.json

فایل `config.example.json` یک نمونه مرجع صرفاً جهت مستندسازی است و توسط اسکریپت‌های `push-to-github.ps1` یا `push-to-github.bat` به‌صورت خودکار خوانده نمی‌شود. هدف از این فایل، نمایش ساختار و نمونه مقادیری است که باید هنگام اجرای دستی یا تعاملی اسکریپت وارد کنید، شامل چهار کلید زیر:

- projectPath : مسیر پوشه پروژه روی دیسک، معادل پارامتر ProjectPath
- repoUrl : آدرس مخزن گیت‌هاب، معادل پارامتر RepoUrl
- commitMessage : پیام کامیت، معادل پارامتر CommitMessage
- branchName : نام شاخه، معادل پارامتر BranchName

می‌توانید از محتوای این فایل برای یادآوری یا الگوبرداری هنگام نوشتن دستور اجرای PowerShell یا هنگام پاسخ به سؤالات فایل bat استفاده کنید.

## آنچه اسکریپت به‌صورت خودکار انجام می‌دهد

1. بررسی نصب بودن برنامه Git روی سیستم و نمایش خطای فارسی واضح در صورت نبود آن، همراه با لینک دانلود.
2. بررسی معتبر بودن مسیر پروژه وارد شده و نمایش خطای فارسی در صورت نبود مسیر.
3. بررسی وجود پوشه `.git` در مسیر پروژه؛ در صورت نبود آن، اجرای خودکار `git init` برای تبدیل پوشه به یک مخزن گیت محلی.
4. بررسی وجود remote با نام `origin`؛ در صورت وجود، به‌روزرسانی آدرس آن با مقدار RepoUrl وارد شده، و در صورت نبود، افزودن remote جدید با همین نام.
5. اجرای `git add -A` برای افزودن تمام فایل‌های جدید، تغییر یافته و حذف‌شده به Stage.
6. بررسی اینکه آیا پس از Add، تغییری برای کامیت وجود دارد یا نه؛ در صورت نبود تغییر، از ساخت یک کامیت خالی و بی‌معنا خودداری می‌شود و پیام مناسب نمایش داده می‌شود.
7. در صورت وجود تغییر، اجرای `git commit` با پیام مشخص‌شده یا پیام پیش‌فرض.
8. اطمینان از قرارگیری روی شاخه مشخص‌شده (BranchName) و در صورت نیاز ایجاد یا سوییچ به آن.
9. اجرای `git push -u origin BranchName` برای ارسال تغییرات به گیت‌هاب و اتصال شاخه محلی به شاخه از راه دور.
10. نمایش پیام موفقیت در صورت تکمیل بدون خطا، یا نمایش پیام خطای فارسی واضح همراه با جزئیات فنی گیت در صورت شکست هر یک از مراحل بالا.

## خطاهای رایج و راه‌حل آن‌ها

نبود Git روی سیستم
پیام: برنامه Git روی این سیستم نصب نیست یا در مسیر PATH قرار ندارد.
راه‌حل: نصب Git از آدرس https://git-scm.com/download/win و باز کردن مجدد پنجره PowerShell یا Command Prompt پس از نصب.

نبود مسیر پروژه
پیام: مسیر پروژه با آدرس وارد شده پیدا نشد.
راه‌حل: بررسی صحیح بودن مسیر وارد شده، از جمله درستی حروف درایو (مانند D:) و نام پوشه‌ها، و اطمینان از وجود فیزیکی پوشه روی دیسک.

آدرس مخزن نامعتبر
پیام: آدرس مخزن وارد شده معتبر به نظر نمی‌رسد و باید با https:// یا git@ شروع شود.
راه‌حل: کپی مجدد آدرس مخزن مستقیماً از صفحه مخزن در گیت‌هاب (دکمه Code) و جلوگیری از وارد کردن فاصله اضافی در ابتدا یا انتهای آدرس.

شکست در Push به دلیل احراز هویت
پیام: خطای مربوط به Authentication failed یا دسترسی غیرمجاز در خروجی گیت.
راه‌حل: بررسی بخش «نکات مهم درباره احراز هویت گیت‌هاب» در همین فایل و اطمینان از استفاده از Personal Access Token به‌جای رمز عبور معمولی در حالت HTTPS، یا تنظیم صحیح کلید SSH در حالت SSH.

شکست در Push به دلیل عقب بودن شاخه محلی از شاخه از راه دور
پیام: خطایی مشابه updates were rejected because the remote contains work که در خروجی گیت نمایش داده می‌شود.
راه‌حل: این حالت معمولاً زمانی رخ می‌دهد که مخزن گیت‌هاب از قبل دارای فایل‌هایی (مانند README ایجادشده هنگام ساخت مخزن) باشد که در مخزن محلی وجود ندارند. برای رفع این مشکل، پیش از اجرای مجدد اسکریپت، یک بار در پوشه پروژه از طریق PowerShell دستور `git pull origin BranchName --allow-unrelated-histories` را اجرا کنید تا تاریخچه‌های دو مخزن ادغام شوند، سپس اسکریپت را دوباره اجرا کنید.

نام شاخه نامتناسب با مخزن از راه دور
توضیح: اگر مخزن گیت‌هاب شما از شاخه پیش‌فرض `master` استفاده می‌کند ولی اسکریپت با مقدار پیش‌فرض `main` اجرا شده باشد، ممکن است دو شاخه مجزا روی گیت‌هاب ایجاد شود.
راه‌حل: پارامتر BranchName را متناسب با نام شاخه پیش‌فرض مخزن گیت‌هاب خود (قابل مشاهده در صفحه اصلی مخزن) تنظیم کنید.

## نکات امنیتی

هیچ‌گاه Personal Access Token یا کلید خصوصی SSH خود را در فایل‌های اسکریپت، فایل config.example.json یا هر فایل دیگری که ممکن است به‌اشتراک گذاشته یا در مخزن عمومی کامیت شود، ذخیره نکنید. این اسکریپت به‌هیچ‌وجه توکن یا رمز عبور شما را در فایل یا متغیر ثابتی نگه نمی‌دارد؛ احراز هویت کاملاً توسط Git و Windows Credential Manager یا عامل SSH سیستم شما مدیریت می‌شود. پیش از اجرای اسکریپت روی یک پروژه، از محتوای پوشه پروژه و اطمینان از نبود اطلاعات حساس (مانند فایل‌های `.env`، کلیدهای API یا رمزهای عبور) در فایل‌هایی که قرار است با `git add -A` کامیت شوند، مطمئن شوید. در صورت نیاز، پیش از اجرای اسکریپت یک فایل `.gitignore` مناسب در ریشه پروژه خود ایجاد کنید تا از ارسال ناخواسته فایل‌های حساس یا غیرضروری (مانند پوشه `node_modules` یا فایل‌های موقت) جلوگیری شود.

## جمع‌بندی سریع برای شروع کار

برای کاربرانی که فقط می‌خواهند هرچه سریع‌تر پروژه خود را Push کنند: ابتدا Git را نصب کنید، یک مخزن خالی در گیت‌هاب بسازید و آدرس آن را کپی کنید، سپس فایل `push-to-github.bat` را دابل‌کلیک کرده و در پاسخ به سؤالات، مسیر پروژه (مثلاً D:\Projects\RedesignApp) و آدرس مخزن کپی‌شده را وارد کنید، پیام کامیت و نام شاخه را در صورت تمایل خالی بگذارید تا مقادیر پیش‌فرض استفاده شوند، و در نهایت با Y تأیید کنید. اگر برای اولین بار است که از این سیستم به گیت‌هاب متصل می‌شوید، هنگام درخواست نام کاربری و رمز عبور، نام کاربری گیت‌هاب و یک Personal Access Token معتبر را وارد کنید.
